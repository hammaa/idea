# 08. AX 설계 — AI를 어디에 놓고, 어디에 놓지 않는가

> **확정 (2026-08-30): 원안의 "ax 처럼"은 AX(AI Transformation)를 뜻한다.**
> [01-기획](01-기획.md) 6절의 마지막 미해결 질문이 해소됐다.

---

## 1. DX와 AX의 차이 — 이 제품에 적용하면

| | DX (디지털 전환) | **AX (AI 전환)** |
|---|---|---|
| 하는 일 | 하던 것을 화면으로 옮김 | **AI가 아니면 못 하던 일을 제품 중심에 놓음** |
| 이 제품에서 | 당구대를 도면으로, 시스템 공식을 계산기로 | **아래 4·5절** |
| 경쟁사 위치 | **3ball·Bricole이 여기까지** — 잘 만든 DX | 비어 있음 |

> **3ball과 Bricole은 DX를 잘 한 제품이다.** 종이 다이어그램을 화면으로 옮기고 솔버를 붙였다.
> **AX는 그 위 단계다** — 그리고 3ball은 **"머신러닝 미사용"** 을 명시적 설계 원칙으로 삼았으므로,
> 이 방향으로는 스스로 가지 않겠다고 선언한 셈이다.

---

## 2. ⚠️ 제1원칙 — **AI는 숫자를 만들지 않는다. 숫자를 읽는다.**

이 제품의 신뢰는 **숫자가 맞고 재현된다는 것** 하나에 달려 있다.
다이아몬드 숫자 하나, 스쿼트 이탈량 하나가 환각이면 **제품 전체가 끝난다.**

```
❌ 금지:  "이 배치는 1쿠션 32를 치세요"  ← AI가 생성한 숫자
✅ 허용:  결정론 엔진이 32를 계산  →  AI가 "왜 32인지" 설명
```

| 영역 | 담당 | 이유 |
|---|---|---|
| 다이아몬드 시스템 계산 | **결정론 산술** | 공식이 정해져 있다. AI를 쓰면 느리고 틀린다 |
| 물리 시뮬레이션 | **결정론 수치해** | 방정식이 알려져 있다 ([02-설계](02-설계.md) 3절) |
| 스쿼트·커브·마찰 | **결정론 모델 + 실측 파라미터** | [07번](07-거리-속도-마찰-모델.md) |
| **설명·진단·코칭** | **AI** | 결정론이 못 하는 일 |
| **입력 인식** | **AI** | 결정론이 못 하는 일 |
| **개인 습관 추출** | **AI/통계** | 결정론이 못 하는 일 |

> **[07번](07-거리-속도-마찰-모델.md)에서 "스쿼트는 속도에 무관하다"를 문헌으로 확인한 것 같은 작업이,
> AI에게 맡겼다면 그럴듯한 오답으로 끝났을 수 있다.**
> 이 도메인은 **자체 검증이 되는 대신, 틀리면 바로 들킨다.**

## 3. AI 계층 4개

```
┌─────────────────────────────────────────────────────────┐
│ ④ 코칭 · 커리큘럼      약점 진단 → 드릴 생성 → 대화형 지도  │  AI
├─────────────────────────────────────────────────────────┤
│ ③ 개인화              실패 로그에서 습관 편향 추출         │  AI/통계
├─────────────────────────────────────────────────────────┤
│ ② 해설                숫자를 말로 옮김                    │  AI  ⭐ 핵심
├═════════════════════════════════════════════════════════┤
│    결정론 엔진        시스템 계산 · 물리 · 괴리 진단        │  ❌ AI 금지
├═════════════════════════════════════════════════════════┤
│ ① 입력                사진 → 공 위치 / 자연어 배치 /       │  AI
│                       영상 → 캘리브레이션 파라미터 역산     │
└─────────────────────────────────────────────────────────┘
```

### ① 입력 — 진입 마찰 제거

| 기능 | 비고 |
|---|---|
| 사진 → 공 3개 위치 | 3ball도 함 (로컬 비전). **동등해지기 위한 기능이지 차별점 아님** |
| 자연어 배치 | "수구 좌하단 코너, 1적구 우측 장쿠션 3번 다이아" |
| **⭐ 영상 → 파라미터 역산** | 사용자가 친 샷 몇 개를 찍으면 **피벗 길이·μs·쿠션 반발 곡선을 역산.** [07번](07-거리-속도-마찰-모델.md) 8절의 캘리브레이션 5개를 자동화 |

> **③번이 진짜다.** 캘리브레이션을 수동으로 시키면 아무도 안 한다.
> **캘리브레이션이 없으면 이 제품의 정확도 우위가 통째로 사라지므로, 이걸 자동화하는 게 사활이 걸린 문제다.**

### ② 해설 — 이 제품의 AI 본체

결정론 엔진의 출력은 숫자 뭉치다. 그걸 **사람이 실행 가능한 문장**으로 바꾼다.

```
[엔진 출력]
  system_first_cushion = 30.0
  physics_first_cushion = 32.1
  delta = +2.1
  breakdown = { squirt: +1.4, swerve: -0.6, cushion: +1.1, datum: +0.2 }
  cue_pivot_in = 9.5, distance_m = 2.0, tips = 2, speed = 3.0

[AI 해설]
  "시스템은 1쿠션 30을 가리키지만 당신 조건에선 32입니다.
   차이 2.1포인트 중 절반이 스쿼트예요 — 피벗 9.5인치 큐로 2팁이면
   2m에서 83mm, 공 하나보다 크게 밀립니다.
   지금은 세게 쳐서 커브가 상쇄를 못 해 주고 있어요.
   → 1팁으로 줄이거나, 같은 2팁이면 조준을 반 포인트 짧게 잡으세요."
```

| 왜 AI여야 하나 | |
|---|---|
| 분해 항목의 **조합이 매번 다르다** | 템플릿으로 못 씀 |
| 원인이 **여러 개일 때 무엇부터 고칠지** 우선순위가 필요 | 판단이 들어감 |
| 사용자 수준에 맞춰 **설명 깊이를 조절** | 입문자에겐 "반 포인트 짧게", 상급자에겐 분해값 전부 |

### ③ 개인화 — 복제 불가능한 자산

물리는 복제된다. 공식도 복제된다. **당신의 실패 로그는 복제되지 않는다.**

```
샷 로그 축적  →  "3팁 이상 롱샷에서 항상 짧다"
              →  스쿼트 보정을 과하게 하는 습관으로 추정
              →  개인 편향값을 모델에 삽입
              →  다음부터 그 사람 기준으로 계산
```

> **최종 계산식 = 시스템 근사 + 물리 보정 + 테이블 보정 + 큐 보정 + `당신의 습관 편향`**
> 앞의 넷은 남도 만들 수 있고, **마지막 하나만 못 만든다.**
> 이것이 [04-수익구조](04-수익구조.md)의 테이블 DB와 함께 **두 개뿐인 해자**다.

### ④ 코칭 — 리텐션 장치

[04-수익구조](04-수익구조.md) 2절에서 **"학습은 끝이 있어서 구독이 안 유지된다"** 는 문제를 지적했다.
개인화된 코칭은 그 문제의 대응이다.

- 약점 진단 → **드릴 자동 생성** ("이번 주: 5/8 두께 2팁 롱샷 20개")
- 성장 추적 → 오차가 줄어드는 것을 수치로
- 대화형 질문 응대 ("왜 이 배치는 플러스가 안 되나요?")

## 4. ⭐ 가장 AX다운 것 — **당신 전용 시스템을 기계가 찾아낸다**

여기가 이 제품이 AX라고 불릴 수 있는 진짜 이유다.

### 발상

> **다이아몬드 시스템은 사람이 손으로 찾아낸 경험적 근사식이다.**
> 파이브앤하프도, 플러스도, 플러스투도 — **누군가가 수십 년간 치면서 찾아낸 회귀식**이다.
>
> **그렇다면 기계가 더 잘 찾을 수 있다.**

### 방법

```
① 물리 엔진으로 정답 데이터 생성
   (당신 큐의 피벗 길이 + 당신 대의 μs·μr·쿠션 곡선으로)
        ↓
② 제약을 걸고 근사식 탐색 (기호 회귀)
   제약: 사람이 테이블에서 암산 가능해야 한다
        - 사칙연산 2회 이하
        - 정수 또는 0.5 단위
        - 다이아몬드 눈금에서 읽을 수 있는 값만 사용
        ↓
③ 유효 범위와 오차를 함께 출력
   "이 식은 수구수 40~70, 2~3팁, 중속에서 오차 ±1.2포인트"
```

### 왜 이게 강한가

| 이유 | |
|---|---|
| **원안의 직관을 그대로 확장한다** | 원안은 "유명한 기본 시스템 데모"였다. 이건 **"당신 조건 전용 시스템 생성"** 이다 |
| **테이블에서 쓸 수 있다** | 물리 시뮬 결과는 경기 중에 못 쓴다. **암산 가능한 식은 쓸 수 있다** ([01-기획](01-기획.md) 2절의 원칙) |
| **결정론 엔진 위에서만 가능** | 정답 데이터를 만들 물리 엔진과 캘리브레이션이 있어야 성립. **순서가 강제된다** |
| **아무도 안 하고 있다** | 3ball은 ML 미사용 선언, Bricole은 기존 8개 시스템 제공 |
| **숫자를 AI가 만들지 않는다** | 식은 탐색으로 나오고, **오차는 물리 엔진으로 검증된 값**이다. 2절 원칙 위배 아님 |

> **"기본 시스템은 남의 대에서 만들어진 식이다. 당신 대에서 맞는 식은 따로 있다."**
> 이 한 문장이 제품의 판매 문구가 될 수 있다.

⚠️ **다만 이건 v2 기능이다.** 물리 엔진 + 캘리브레이션 + 검증이 먼저 서야 한다.
그리고 **"기계가 찾은 식이 실제로 맞는지"는 당구대에서 검증해야 한다** — 다행히 이 도메인은 그게 된다.

## 5. 비용과 제약

| 항목 | 판단 |
|---|---|
| **오프라인 동작** | **핵심 기능(계산·궤적·감도표)은 AI 없이 동작해야 한다.** 당구장 네트워크를 신뢰할 수 없고, 3ball·Bricole 모두 오프라인 동작 |
| AI 호출 비용 | 해설은 샷당 1회. 사용자 규모가 작아 부담 크지 않음 ([05-매출예측](05-매출예측.md)) |
| 지연 | 해설은 비동기로. **숫자는 즉시, 말은 나중에** |
| 비전 | 온디바이스 우선 (3ball이 로컬 비전으로 함) |
| 기호 회귀 | 서버 배치 작업. 실시간 아님 |

## 6. 안 하는 것

| 안 함 | 이유 |
|---|---|
| **AI로 궤적 예측** | 결정론이 더 정확·빠르고, 틀리면 신뢰가 무너진다 |
| **AI로 시스템 숫자 생성** | 환각 1건 = 제품 사망 |
| LLM에게 물리 계산 시키기 | 산술은 코드가 한다 |
| AI 캐릭터·챗봇 UI 전면화 | 이 제품의 사용자는 **숫자를 보러 온다** |

---

## 7. 로드맵에서의 위치

| 단계 | AI 계층 |
|---|---|
| **v0** | 없음 — 결정론 엔진 + 감도표만. **정확도부터 증명** |
| **v1** | ② 해설, ① 사진 입력 |
| **v1.5** | ③ 개인화, ④ 코칭 (리텐션 문제 대응) |
| **v2** | ⭐ **시스템 자동 발견**, ① 영상 캘리브레이션 자동화 |

> **v0에 AI를 넣지 않는 것이 중요하다.**
> **틀린 숫자를 예쁘게 설명하는 것보다 나쁜 것은 없다.** 숫자가 먼저 맞아야 한다.

---

## 8. 정리

| 질문 | 답 |
|---|---|
| AI를 어디에 놓나 | **입력 · 해설 · 개인화 · 코칭.** 결정론 엔진의 **바깥** |
| AI를 어디에 놓지 않나 | **숫자를 만드는 모든 곳** |
| 그럼 AX가 맞나 | ✅ **AX의 정의 그대로다** — 결정론 코어 위에 AI 계층을 얹어, AI가 아니면 못 하던 일(설명·개인화·시스템 발견)을 제품 중심에 놓는다 |
| 가장 AX다운 기능은 | ⭐ **당신 큐·당신 대 전용 시스템을 기계가 찾아내는 것** (4절) |
| 언제 넣나 | **v0에는 안 넣는다.** 숫자가 맞는 게 먼저 |

### 한 문장

> **경쟁 서비스는 당구대를 화면으로 옮겼다(DX).**
> **이 제품은 "당신의 큐, 당신의 대, 당신의 습관"을 계산에 넣고, 그 결과를 말로 설명한다(AX).**
> **그리고 계산 자체는 끝까지 결정론이 한다.**
