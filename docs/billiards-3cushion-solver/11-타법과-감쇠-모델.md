# 11. 타법과 감쇠 — 밀어치기는 왜 다른가

> **사용자 3차 피드백 (2026-08-31, [감도 데모](mockup/) 실사용):**
> ① 밀어치면 회전도 더 먹고 앞으로 가는 힘이 가중되는데 그 로직이 없다
> ② 2·3쿠션쯤 되면 속도와 회전이 같이 줄어드는 것도 없다
> ③ 큐가 공을 치고 **15cm 더 나가게 밀어치는 것**, **공만 딱 치고 멈추는 것**, **세게 밀어치는 것**이 전부 다르다
> ④ 목업에 2팁은 있는데 **당점 위치가 없다**
> ⑤ **다이아 단위가 무엇인지 모르겠다**
> ⑥ **프레임의 점(다이아몬드) 기준이 맞나**

---

## 1. ⚠️ 팔로우스루에 대한 정정 — 관측은 맞고, 원인은 다르다

### 실측 문헌

> **팁이 공에 닿아 있는 시간은 약 0.001초다.**
> **팔로우스루는 공에 직접 영향을 주지 못한다 — 팔로우스루가 일어나는 시점에 공은 이미 떠났다.**
> **공이 아는 것은 임팩트 순간의 ① 팁 접촉점 ② 큐 속도 ③ 큐 각도·기울기 셋뿐이다.**
> 팔로우스루는 원인이 아니라 **스트로크 품질의 지표(symptom)** 다.

### 그런데 사용자의 관측은 왜 맞는가

**세 타법이 다른 것은 사실이다. 다만 "15cm 더 나가서"가 아니라, 세 타법이 임팩트 순간에 서로 다른 (타점, 속도)를 만들기 때문이다.**

| 타법 | 세로 타점 | 큐 속도 | 결과 |
|---|---|---|---|
| **공만 딱 치고 멈춤** (잽·펀치) | 중단 | 중~고 | **스턴** — 미끄럼 길고, 분리각 90° |
| **15cm 밀어냄** (부드러운 밀어치기) | **상단** | 중~저 | **오버스핀** — 미끄럼 없음, 앞으로 흐름 |
| **세게 밀어치기** | 상단 | **고** | 오버스핀 + 큰 속도 |

> ### **그래서 진짜 결손은 "팔로우스루 로직"이 아니라 「세로 타점」축이 통째로 빠져 있었던 것이다.**
> 사용자 지적 ④(당점 위치가 없다)와 ①③이 **같은 문제**였다.
> 세로 타점을 넣으면 세 타법이 자동으로 구분된다 — 별도 로직이 필요 없다.

⚠️ **다만 게임 조작으로는 팔로우스루를 입력으로 받는 것이 옳다** ([10-게임-설계](10-게임-설계.md) 3절 ⑥).
문헌이 "팔로우스루는 스트로크 품질의 **지표**"라고 한 것은, 거꾸로 **지표에서 원인을 읽어도 된다**는 뜻이다.
드래그 궤적 → (세로 타점, 속도)로 역매핑하는 설계는 물리와 모순되지 않는다.

## 2. 세로 타점의 정확한 물리 — 상한이 존재한다

임팩트 지점이 공 중심에서 `b`만큼 위일 때:

```
ω / v = 5b / (2R²)          자연 구름 조건: ω/v = 1/R
오버스핀 비율 = 5b / (2R)     [1.0 = 자연 구름]
```

캐롬 공 R = 30.75mm, 1팁 = 5mm 가정:

| 세로 타점 b | b/R | 팁 | **오버스핀 비율** | 상태 |
|---:|---:|---:|---:|---|
| −15.38 mm | −0.50 | −3.08 | **−1.25** | **미스큐 한계 (백스핀 최대)** |
| −12.30 mm | −0.40 | −2.46 | −1.00 | 끌어치기 |
| 0 | 0 | 0 | 0 | **스턴 (중단)** |
| +7.70 mm | +0.25 | +1.54 | +0.63 | 미끄럼 후 구름 전이 |
| **+12.30 mm** | **+0.40** | **+2.46** | **1.00** | ⭐ **자연 구름 타점 — 미끄럼 없이 바로 구른다** |
| **+15.38 mm** | **+0.50** | **+3.08** | **1.25** | **미스큐 한계 = 최대 오버스핀** |

### 여기서 나오는 두 개의 딱딱한 사실

> **① 미스큐 한계는 `|b| ≤ R/2` = 15.38mm = 약 3.08팁이다.**
> **현재 목업의 "4팁"은 물리적으로 칠 수 없는 값이다** — 미스큐 난다. **버그로 고쳐야 한다.**
>
> **② 밀어치기로 얻을 수 있는 오버스핀의 상한은 자연 구름의 1.25배다.**
> 아무리 밀어도 그 이상은 물리적으로 불가능하다. "더 밀면 더 간다"에는 천장이 있다.

### 자연 구름 타점(2R/5)의 의미

**b = 0.4R을 정확히 치면 공은 미끄러지지 않고 처음부터 구른다.**
[06번](06-입력-파라미터-모델.md) 2절의 미끄럼 전이 거리 `d = 12v²/49μg`가 **0이 된다.**
→ 커브도 안 생기고, 분리각은 즉시 30° 법칙 영역이며, **아래 3절의 회전 보존이 최대가 된다.**

## 3. ⭐ "밀어치면 회전도 더 먹는다"의 정체 — 미끄럼이 회전을 먹는다

사용자 지적 ①의 후반부. **같은 좌우 타점(팁 수)이면 초기 사이드스핀 비율 `ω/v`는 같다.**
그런데 쿠션에 도착했을 때 남아 있는 회전은 다르다.

| 구간 | 사이드스핀에 작용하는 마찰 | 크기 |
|---|---|---|
| **미끄러지는 동안** | 미끄럼 마찰이 회전과 병진에 동시에 작용 | **크다** |
| **구르는 동안** | 수직축 스핀 마찰(드릴링)만 | **작다** |

> ### **미끄럼 구간이 길수록 회전을 더 많이 잃는다.**
> **밀어치기(오버스핀)는 미끄럼 구간이 아예 없거나 짧다 → 회전이 그대로 살아서 쿠션에 도착한다.**
> **세게 끊어치기(스턴)는 미끄럼이 길다 → 도착 전에 회전을 상당량 소모한다.**

### 실제로 계산해 보면

`e=0.85` · 쿠션당 회전 잔존 `0.75` · 쿠션 간 1.5m · `k_구름=0.06/m` · `k_미끄럼=0.35/m` **(계수 전부 미확정)**

| 타법 | 1쿠션 | 2쿠션 | **3쿠션** |
|---|---|---|---|
| **밀어치기** (오버스핀, 미끄럼 0m) | 속도 83.6% / 회전 **62.6%** | 69.4% / **42.9%** | 56.9% / **29.4%** |
| 보통 (중단, 3 m/s, 미끄럼 1.12m) | 83.6% / 45.3% | 69.4% / 31.0% | 56.9% / **21.3%** |
| 세게 끊어치기 (4.5 m/s, 미끄럼 2.53m) | 83.6% / 28.3% | 69.4% / 19.4% | 56.9% / **13.3%** |

> **3쿠션에서 밀어치기는 29.4%, 세게 끊어치기는 13.3% — 2.2배 차이다.**
> **속도는 셋 다 같은데 회전만 다르다.** 사용자가 느낀 "밀어치면 회전이 더 먹는다"가 이것이다.

### 그리고 사용자 지적 ② — 속도와 회전은 같이 줄어든다

**둘은 서로 다른 속도로 줄어든다.** 위 표에서 3쿠션 시점:

```
속도 : 56.9%  (쿠션 반발 e가 지배)
회전 : 13~29% (미끄럼·구름 마찰 + 쿠션 전이 손실이 지배)
```

> **회전이 속도보다 훨씬 빨리 죽는다.** [06번](06-입력-파라미터-모델.md) 3절에서
> "3팁을 줬다는 건 1쿠션의 회전이지 3쿠션의 회전이 아니다"라고 쓴 것이 여기서 숫자로 확인된다.

## 4. 오버스핀과 목적구 충돌 후 전진력

사용자 지적 ① 전반부 — "앞으로 가는 힘이 가중된다".

```
목적구 충돌
  → 수구의 병진 속도는 대부분 목적구로 넘어간다
  → 그런데 수구의 자전(스핀)은 충돌로 거의 사라지지 않는다
  → 남은 톱스핀이 마찰을 통해 다시 병진으로 바뀐다
  → 수구가 "먹고" 앞으로 다시 나간다
```

| 도착 시 회전 상태 | 충돌 후 수구 |
|---|---|
| 백스핀 | 뒤로 되돌아옴 (끌어치기) |
| 스턴 (회전 0) | 접선 방향으로 정지성 이동 — **90° 법칙** |
| 자연 구름 (1.0) | 앞으로 흐름 — **30° 법칙** |
| **오버스핀 (~1.25)** | **30° 법칙보다 더 앞으로 파고듦** |

> **[06번](06-입력-파라미터-모델.md) 2절의 분리각 표에 "오버스핀" 행이 빠져 있었다.**
> 스턴 60° ↔ 자연구름 34° 사이만 있었고, **34°보다 더 작은 영역(오버스핀)** 이 없었다.

## 5. 다이아몬드 기준 — 사용자 지적 ⑥에 대한 답

> **질문: 보통 당구대에 있는 프레임 점을 기준으로 하는데, 그렇게 된 거 맞니?**
>
> **답: 맞다. 다만 목업이 그걸 화면에 표시하지 않아서 확인할 방법이 없었다 — 그건 목업의 잘못이다.**

### 다이아몬드의 물리적 위치

| 항목 | 값 |
|---|---|
| 위치 | **레일(프레임) 위**, 유효 타면이 아님 |
| 쿠션 노즈로부터 | 약 **3 11/16 인치 ≈ 94 mm** 바깥 |
| 배치 | **서로 등간격이며, 쿠션의 반사 지점으로부터도 등간격** |
| 길이 방향 | 유효 타면을 **장쿠션 8등분 · 단쿠션 4등분** |

**국제식 대대 2844 × 1422 mm 에서:**

```
2844 ÷ 8 = 355.5 mm
1422 ÷ 4 = 355.5 mm      →  정사각 격자. 다이아 1칸 = 355.5 mm
```

### 목업이 쓰는 좌표계 (명시)

| 것 | 기준 |
|---|---|
| 다이아 눈금 | **장쿠션 0–8 / 단쿠션 0–4**, 코너 = 0 |
| 1다이아 | **355.5 mm** |
| 쿠션 도달점 | 공 중심을 쿠션에 수직 투영한 위치 = **공이 쿠션 천에 닿는 지점** |

> ⚠️ **이 값은 "기하학적 다이아 인덱스"이지 시스템 숫자가 아니다.**
> 파이브앤하프의 수구수 50·40·30 같은 값은 이 인덱스에 **시스템별 척도를 다시 입힌 것**이다.
> 그리고 [02-설계](02-설계.md) 2절에서 정리했듯 시스템 안에서도
> **수구수·1쿠션수는 당점 기준, 3쿠션수는 공이 쿠션 천에 닿는 부위 기준**으로 데이텀이 갈린다.
> **목업은 후자(접촉점) 하나만 쓴다.** 시스템 숫자표를 넣을 때 이 변환을 반드시 명시해야 한다.

## 6. 목업에 반영한 것

| 지적 | 조치 |
|---|---|
| ① 밀어치면 회전 더 먹고 앞으로 감 | **오버스핀 비율 표시** + 회전 감쇠에 미끄럼 거리 반영 |
| ② 2·3쿠션에서 속도·회전 감쇠 없음 | **쿠션별 속도·회전 잔존율 표** 신설 |
| ③ 세 가지 타법 | **타법 프리셋 3종** — 딱 끊어치기 / 밀어치기 / 세게 밀어치기 |
| ④ 당점 위치가 없음 | **2D 당점 피커** — 미스큐 한계 원, 자연 구름 타점 표시 |
| ⑤ 다이아 단위 모름 | **도면에 다이아 번호 표기** (장 0–8 / 단 0–4) + 1다이아 = 355.5mm 명시 |
| ⑥ 프레임 점 기준인가 | **기준 설명 패널** 추가 (쿠션 노즈 +94mm, 등간격) |
| — | **미스큐 한계 초과(4팁) 버그 수정** — 최대 약 3.08팁 |
