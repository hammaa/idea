# 02. 설계 — 3층 구조와 AI의 자리

조사일 2026-08-30

---

## 1. 전체 구조

```
                 ┌──────────────────────────────────────┐
   공 배치 입력  │  ① 시스템 계산 엔진 (결정론적 산술)   │  "수구수 50 − 3쿠션수 20 = 1쿠션수 30"
   (수동 드래그) │     파이브앤하프 / 플러스 / 플러스투   │  → 사람이 테이블에서 재현 가능한 절차
        │        └──────────────────────────────────────┘
        │                        │
        ├────────▶ ┌──────────────────────────────────────┐
                   │  ② 물리 시뮬레이션 (오픈소스 활용)    │  실제 궤적, 1~8쿠션 도달점
                   │     스핀·쿠션반발·스쿼트·커브         │
                   └──────────────────────────────────────┘
                                 │
                   ┌──────────────────────────────────────┐
                   │  ③ 괴리 진단 (⭐ 이 제품의 본체)      │  "시스템 30 vs 물리 32 (+2)"
                   │     차이 + 원인 분해 + 팁 감도표      │  "스쿼트 1.4 / 커브 0.6"
                   └──────────────────────────────────────┘
```

**①과 ②는 목적이 다르다.**

| | ① 시스템 계산 | ② 물리 시뮬 |
|---|---|---|
| 성격 | 경험적 **근사 공식** | 미분방정식 수치해 |
| 정확도 | 특정 조건에서만 | 파라미터가 맞으면 높음 |
| **테이블에서 쓸 수 있나** | ✅ **암산 가능** | ❌ 컴퓨터 필요 |
| 존재 이유 | 사람이 실행하기 위해 | 진실을 알기 위해 |

> **둘 다 필요하다.** 물리만 있으면 경기 중에 못 쓰고, 시스템만 있으면 왜 빗나갔는지 모른다.
> **③이 둘을 잇는 다리이고, 그게 상품이다.**

## 2. ① 시스템 계산 엔진

### 구현할 시스템

| 시스템 | 공식 | 기본 당점 | 검증 상태 |
|---|---|---|---|
| **파이브앤하프 (Corner-5)** | **수구수 − 3쿠션수 = 1쿠션수** | 2~3팁 | ✅ 공식 확인 |
| **플러스** | **수구수 + 1쿠션수 = 3쿠션수** | **상단 2팁** | ✅ 공식 확인 |
| **플러스투 (Plus-2)** | 수구수 + 1쿠션수 기반, **2를 더하는** 변형 | **중단 3팁** (3시/9시) | ⚠️ 자료마다 표기가 갈림 → 아래 주의 |
| 볼값 시스템 (앞돌리기·옆돌리기) | **1적구수 + 도착수 + 기울기(보정)** | 두께·팁 분배 | ✅ 구조 확인 |
| 리버스 / 크로스테이블 / 엔드레일 | — | — | Bricole이 8종 제공 → 확장 후보 |

### ⚠️ 반드시 반영해야 할 구현 함정

**(1) 숫자마다 기준점이 다르다**

> **수구수·1쿠션수는 "당점" 기준인데, 3쿠션수는 당점이 아니라 "쿠션 천이 공과 닿는 부위" 기준이다.**

즉 **같은 도면 위에서 좌표계가 두 개**다. 이걸 한 좌표계로 뭉뚱그리면 공 반지름(약 30mm)만큼 어긋나고,
포인트 단위로는 **0.5~1포인트 오차**가 상시 발생한다. 시스템이 "안 맞는" 흔한 원인이다.

**(2) 출발 위치에 따른 보정이 필수다**

수구수 50에서 출발할 때와 30에서 출발할 때, **같은 3쿠션 20을 보내려 해도 1쿠션수가 다르다.**
"50보다 작으면 더하고, 크면 뺀다" 형태의 보정표가 시스템마다 붙는다.
→ **보정표를 데이터로 분리**하고 코드에 하드코딩하지 않는다.

**(3) 테이블 규격 의존**

국제식 대대는 **2844 × 1422 mm, 쿠션 높이 37~38mm**. 중대는 규격이 다르므로 **숫자 체계가 통째로 달라진다.**
→ 테이블 타입을 최상위 설정으로 둔다.

**(4) 다이아몬드 숫자표는 별도 전사(轉寫) 작업이 필요하다**

이번 조사에서 **공식은 확인했으나 다이아몬드별 숫자 전체 표는 신뢰할 만한 출처로 확정하지 못했다.**
표준 교재를 놓고 전사한 뒤, **당구대에서 실제로 쳐서 검증**하는 절차를 반드시 거친다.
→ **추정으로 채워 넣으면 안 된다.** 이 제품에서 숫자 하나가 틀리면 신뢰가 통째로 무너진다.

## 3. ② 물리 엔진 — 자체 개발하지 않는다

오픈소스가 이미 필요한 물리를 다룬다.

| 후보 | 특징 |
|---|---|
| [tailuge/billiards](https://github.com/tailuge/billiards) | 브라우저, WebGL. **백스핀·사이드스핀·쿠션 반발 모델링**. 3쿠션 트레이너 포함 |
| [pooltool](https://ekiefl.github.io/2021/03/25/pooltool-start/) | 파이썬. 방정식→코드 전환 과정이 문서화되어 있음 |

**전략: 물리 엔진은 가져다 쓰고, 개발력을 전부 ③ 괴리 진단에 넣는다.**

> ⚠️ **다만 오픈소스 엔진을 그대로 쓰면 3ball과 같은 한계에 걸린다.**
> 실사용 결과 3ball은 **두께·스트로크 타입·스쿼트·커브·큐 특성·회전 감쇠**가 모델에 없다.
> 엔진의 **적분기와 충돌 처리는 가져오되, 입력 파라미터 공간은 새로 정의해야 한다.**
> → **[06-입력-파라미터-모델.md](06-입력-파라미터-모델.md)** 가 그 사양이다.

### 모델링해야 할 효과 (원안 4번)

| 효과 | 정의 | 좌우하는 변수 |
|---|---|---|
| **스쿼트 (Squirt / 큐볼 디플렉션)** | 사이드스핀을 줄 때 수구가 **겨냥선에서 벗어나 출발**하는 각변위 | 팁 오프셋(회전량), **샤프트 끝단 질량(endmass)**, 스트로크 속도 — **팁 오프셋과 속도가 클수록 커진다** |
| **커브 (Swerve)** | 큐를 세워 칠 때 수구가 미끄러지며 **휘어 돌아오는 것** | 속도, 거리, 회전량, **큐 세운 각도**, 공·천 상태 |
| **넷 디플렉션 ("Squerve")** | 스쿼트와 커브의 **합성** — 실제로 목적구에 닿을 때의 최종 이탈량 | 위 전부 |
| **스로우 (Throw)** | 공-공 접촉 시 마찰로 목적구가 밀리는 것 | 두께, 회전, 접촉면 상태 |

> **핵심:** 스쿼트와 커브는 **방향이 반대라 서로 상쇄**된다.
> 그래서 "밀어치기 vs 그냥 치기"(속도·큐 각도 차이)에 따라 **합성 결과가 달라지고**, 원안 4번이 요구한 게 정확히 이 계산이다.

### 개인 보정 — 피벗 길이

스쿼트 보정은 큐마다 다르다. **"자연 피벗 길이(natural pivot length)"** 는 샤프트마다 달라서
**사용자 장비에 맞춰 캘리브레이션해야** 깔끔하게 상쇄된다. 저디플렉션 샤프트를 쓰면 스쿼트가 줄어든다.

> **설계 함의:** 스쿼트 계산은 **사용자별 파라미터 1개(피벗 길이)** 를 받아야 의미가 있다.
> 이 값을 측정하는 온보딩 절차(2~3구 테스트 샷)를 넣는 것이 정확도의 절반을 좌우한다.
>
> ⚠️ **"나무 큐/카본 큐" 선택지로 만들면 안 된다.** 실측상 카본이라고 자동으로 저디플렉션이 아니다.
> 재질이 아니라 **피벗 길이(인치)** 를 재서 받아야 한다. → [06번](06-입력-파라미터-모델.md) 4절

## 4. ③ 괴리 진단 — 이 제품의 본체

### 출력 1: 괴리 분해

```
배치: 수구 장쿠션 50, 목표 3쿠션 20

  시스템(파이브앤하프) 계산  1쿠션 = 30.0
  물리 시뮬 (2팁, 중속)      1쿠션 = 32.1
  ─────────────────────────────────────
  괴리 +2.1 포인트
     ├ 스쿼트        +1.4   (2팁, 현재 속도)
     ├ 커브          −0.6   (큐 각도 3°)
     ├ 쿠션 반발 보정 +1.1   (테이블 캘리브레이션값)
     └ 기준점 차이    +0.2   (3쿠션수는 접촉면 기준)
```

### 출력 2: 팁 감도표 (⭐ 원안 3번)

> 감도의 축은 팁 하나가 아니다. **두께(8단계) × 팁(0~4) × 세기(1~5) × 스트로크 타입**이 전부 축이다.
> 축 정의는 [06-입력-파라미터-모델](06-입력-파라미터-모델.md) 5절 참조.

```
        1쿠션   2쿠션   3쿠션   4쿠션 ...
 0팁     28.0    ...     18.2    ...
 1팁     29.4    ...     22.1    ...     ← 1팁당 3쿠션 +3.9
 2팁     30.9    ...     26.3    ...     ← 1팁당 +4.2
 3팁     32.5    ...     31.0    ...     ← 1팁당 +4.7   (비선형!)
 4팁     34.2    ...     36.4    ...
```

> **비선형성이 보이는 것 자체가 가치다.** "1팁 = 4포인트"라는 어림값이 **어디서 깨지는지**를 알려준다.

### 출력 3: 시스템 유효 범위

각 시스템이 **어떤 구간에서 오차 몇 포인트 이내인지**를 색으로 칠한 맵.
Bricole이 "each with its own formula and its own **range**"라고 표현한 부분과 겹치므로 **차별화 여지 확인 필요.**

## 5. AI를 어디에 놓는가 — 원안 7번

> **3ball은 "머신러닝 미사용, 순수 물리 기반 검색"이라고 명시한다.** 이건 약점이 아니라 **의도적 선택**이다.

궤적 계산에 AI를 쓰면 **결정론이어야 할 것을 확률로 바꾸는 퇴보**다. 당구 물리는 방정식이 알려져 있다.

| 영역 | AI 적합 | 이유 |
|---|:-:|---|
| 궤적·시스템 계산 | ❌ | **결정론적 물리/산술이 더 정확하고 빠르고 검증 가능.** 여기 AI를 넣으면 안 됨 |
| **사진 → 공 위치 인식** | ✅ | 비전. 단 3ball이 이미 로컬 비전으로 제공 |
| **자연어 설명·코칭** | ✅✅ | "왜 이 해법인가", "왜 빗나갔나"를 말로 풀어줌. **계산 결과를 입력으로 받는 서술 계층** |
| **개인화** | ✅✅ | 사용자의 실패 로그를 읽어 "당신은 3팁에서 항상 짧다" 같은 패턴 발견 |
| 문제(드릴) 생성·난이도 조절 | ✅ | 커리큘럼 자동화 |
| 자연어 입력 ("좌하단에 수구, 우상단 코너 근처 적구") | ✅ | 입력 편의 |

> **결론: AI는 엔진이 아니라 인터페이스·해설·개인화 계층이다.**
> **계산은 결정론이 하고, AI는 그 결과를 말로 옮기고 사람에 맞춘다.**

⚠️ 원안의 **"ax 처럼"** 이 무엇을 가리키는지 확인이 필요하다 ([01-기획](01-기획.md) 6절 질문 3).
AX(AI Transformation)를 뜻한다면 위 배치가 정확히 그 형태다 — **기존 결정론 엔진 위에 AI 계층을 얹는 것**.

## 6. 테이블 캘리브레이션 — 빠뜨리면 전부 무의미

다이아몬드 시스템은 **테이블 상태에 따라 보정값이 달라진다.** 천의 상태, 습도, 온도, 사용 연수에 따라 반발이 변한다.

```
온보딩: 표준 뱅크샷 3~5개를 치게 하고 실제 도착점을 입력받음
   ↓
쿠션 반발 계수 + 천 마찰 계수를 역산
   ↓
이후 모든 계산에 이 테이블의 보정값 적용
```

Bricole도 **테이블 캘리브레이션**을 제공한다 → **선택 기능이 아니라 필수 기능**으로 봐야 한다.

그리고 여기서 사업적으로 가장 흥미로운 것이 나온다:

> **캘리브레이션 결과를 "장소 × 테이블 번호"로 축적하면, 그건 아무도 복제할 수 없는 데이터가 된다.**
> → [04-수익구조](04-수익구조.md) 4절.

## 7. 기술 스택 방향 (v0)

| 층 | 선택 | 근거 |
|---|---|---|
| 클라이언트 | **웹 / PWA** | 3ball이 웹+PWA로 성공적으로 동작. 앱스토어 우회, 배포 빠름 |
| 물리 | 오픈소스 엔진 포팅 | 자체 개발 금지 |
| 시스템 계산 | 순수 함수 + **외부 데이터 파일**(숫자표·보정표) | 검증·수정이 코드 배포 없이 가능해야 함 |
| **입력 파라미터** | 두께 8단계 / 타점(세로·가로) / 세기 / 큐 각도 / 스트로크 프리셋 + 개인값(피벗 길이·μ·쿠션계수) | **[06번](06-입력-파라미터-모델.md)** 이 사양서 |
| AI | API 호출 (해설·개인화만) | 엔진 아님. 오프라인에서도 핵심 기능은 동작해야 함 |
| 저장 | 로컬 우선 | 3ball이 로컬 저장으로 계정 없이 운영 |
