# Squerve

> **당신의 큐로 계산하는 3쿠션 캐롬 시뮬레이터**
> A three-cushion carom simulator where the physics — and your own cue — are the game rules.

<sub>*가제(working title). `squerve`는 스쿼트(squirt)와 커브(swerve)의 합성어로, 이 프로젝트가 유일하게 제대로 모델링하는 현상의 이름이다. 대안: `carom-lab`, `pivot`*</sub>

---

## 무엇인가

**1인칭 3쿠션 캐롬 시뮬레이션 게임.** Unity로 만들고 **PC 우선, 모바일 병행**.

일반적인 당구 게임과 두 가지가 다르다.

1. **물리가 게임 규칙이다.** 밸런스 수치를 따로 두지 않는다. 난이도도, 장비 성능도 전부 물리 파라미터에서 나온다.
2. **조준이 몸으로 하는 절차다.** 큐를 들어 각을 재고, 자리를 잡고, 낮게 앉아 두께를 보고, 백스윙으로 타법이 결정된다.

## 다른 점 세 가지

### 1. 물리 충실도 — 경쟁 서비스에 없는 5가지를 모델링한다

3ball을 실제로 플레이해 확인한 결손 목록이 곧 이 프로젝트의 사양이다.

| 결손 | 이 프로젝트 |
|---|---|
| 스쿼트·커브 미계산 | **피벗 길이 기반 스쿼트 + 미끄럼 구간 기반 커브, 둘의 합성** |
| 큐 특성 미반영 | **자연 피벗 길이가 스쿼트각을 직접 결정** |
| 두께가 입력 축에 없음 (각도만) | **두께 8단계 ↔ 절단각, 겹침으로 보는 1인칭 조준** |
| 회전 가중치(감쇠) 부실 | **미끄럼/구름 구간별 회전 감쇠 + 쿠션당 손실** |
| 스트로크 타법 미반영 | **세로 타점 축 + 백스윙 판정** |

### 2. ⭐ 장비 스탯을 지어내지 않는다 — 실제 물리 파라미터가 스탯이다

| 아이템 | 흔한 구현 | 이 프로젝트 |
|---|---|---|
| 큐 | "정확도 +5" | **자연 피벗 길이 (인치)** |
| 팁 | "파워 +3" | **미스큐 한계 오프셋**, 팁-공 마찰 |
| 초크 | 소모품 | 팁 마찰 |
| 천 · 쿠션 | 스킨 | **μs · μr · 반발 곡선** |

그리고 여기서 이 게임의 정체성이 나온다. 순 이탈량(mm), 2팁·큐각도 3°·μ=0.20·거리 2m:

| 큐 | v=1.5 | v=2.5 | v=3.5 | v=4.5 | v=5.5 |
|---|---:|---:|---:|---:|---:|
| 목재 9.5" | 39.8 | 44.6 | 51.7 | 67.4 | 72.5 |
| 중급 13" | 17.5 | 22.2 | 29.4 | 45.1 | 50.2 |
| **저디플렉션 19"** | **−1.7** | 3.1 | 10.3 | 25.9 | 31.1 |

> ### **"더 좋은 큐"가 존재하지 않는다. 거리·속도 대역마다 유리한 큐가 다르다.**
> **저스쿼트 큐는 느린 롱샷에서 부호가 뒤집힌다** — 스쿼트가 작아 커브가 상쇄할 상대를 잃기 때문이다.
> **pay-to-win이 밸런싱이 아니라 물리 때문에 구조적으로 불가능하다.**

### 3. 1인칭 조준 시퀀스

당구의 실력은 치는 순간이 아니라 치기 전 30초에 있다. 그 30초를 게임 단계로 만든다.

| 단계 | 내용 |
|:-:|---|
| ① 관찰 | 테이블을 돌며 배치를 본다 |
| ② **각 재기** | 큐를 눈앞에 세워 겨냥선을 본다. 연장선이 어느 포인트에 닿는지 |
| ③ 자리잡기 | 스탠스·시선 정렬 → 시야가 낮아진다 |
| ④ **두께 확인** | 카메라가 공 높이로. **겹침 비율이 곧 두께** (반두께 = 적구 절반이 가려짐) |
| ⑤ 당점 조준 | 근접 뷰에서 상하·좌우 미세 조정 |
| ⑥ **스트로크** | 드래그 궤적 하나에서 **속도·세로타점·큐각도**를 읽는다 |

**조준 보조는 기본 꺼짐.** 켜면 기록이 분리된다 — 보조를 켜면 기존 게임들과 같아진다.

## 물리 모델

**이 레포의 핵심 자산.** 전부 문헌 확인 또는 직접 유도한 것이고, 미확정 계수는 명시한다.

### 확정된 공식

```
두께 ↔ 절단각          sin θ = 1 − f              f = 두께 비율 (8/8 = 정면)
                       반두께(4/8) → 30.00°,  1/8 → 61.04°

당점 → 회전            ω / v = 5b / (2R²)         b = 중심에서의 타점 오프셋
오버스핀 비율           s = 5b / (2R)              1.0 = 자연 구름
  · 미스큐 한계         |b| ≤ R/2 = 15.38 mm       ≈ 3.08 팁 (1팁 = 5mm)
  · 자연 구름 타점       b = 2R/5 = 12.30 mm        미끄럼 없이 바로 구른다
  · 오버스핀 상한        s = 1.25                   물리적 최댓값

미끄럼 → 구름 전이      d = (2v²/7μg) · (|1−s| − (1−s)²/7)
                       s=0 이면 12v²/49μg 로 환원

스쿼트각               tan θ = 팁 오프셋 / 자연 피벗 길이     속도와 무관
커브 (미끄럼 중)        a = C · sin(큐각도) · (오프셋/미스큐한계)
                       Δφ = atan( 2a / 7μg )                 속도와 무관
                       d ≤ ds : ½·a·(d/v)²
                       d > ds : ½·a·ts² + (d − ds)·tan(Δφ)     ts = 2v/(7μg)
순 이탈                스쿼트 − 커브   ("squerve")

분리각                 스턴  → 90° 법칙 (수구는 접선 방향)
                       구름  → 30° 법칙 (두께 1/4~3/4, 반두께에서 최대 34°)
                       오버스핀 → 30°보다 더 앞으로 파고든다
```

### 마찰은 하나가 아니라 셋이다

| # | 마찰 | 값 | 지배하는 것 |
|:-:|---|---|---|
| 1 | **미끄럼** μs | 0.15 ~ 0.25 | 전이 거리 · 커브량 · 분리각 |
| 2 | **구름 저항** μr | 0.005 ~ 0.015 | 긴 경로 속도 감쇠 (3쿠션은 6~10m) |
| 3 | **스핀 마찰** | 미확정 | 사이드스핀 감쇠 = "회전이 먹는다" |

> **"대가 빠르다/느리다"는 ①②, "회전이 잘 먹는다"는 ③이다. 뭉치면 둘 중 하나는 반드시 틀린다.**

### ⭐ 밀어치기가 회전을 보존하는 이유

미끄러지는 동안에는 회전을 크게 잃고, 구르는 동안에는 적게 잃는다.
**밀어치기(오버스핀)는 미끄럼 구간이 없거나 짧다.**

| 타법 | 미끄럼 | **3쿠션 회전 잔존** |
|---|---:|---:|
| 부드럽게 밀어치기 | 0.05 m | **31.8%** |
| 세게 밀어치기 | 0.15 m | 30.9% |
| 공만 딱 치고 멈춤 (스턴) | 1.53 m | **20.8%** |
| 끌어치기 | 2.47 m | 20.8% |

*(μ=0.20, e=0.85, 쿠션당 회전 잔존 0.75, 쿠션 간 1.5m — 계수는 미확정)*

> 당구계의 경험칙 — *"리버스는 임팩트 후 큐를 10cm 더 밀어내면 회전이 살아 세게 안 쳐도 된다"* —
> 과 이 모델이 **독립적으로 같은 결론에 도달했다.**

### ⚠️ 정직성 규칙 — 모든 상수에 상태를 붙인다

| 배지 | 뜻 | 예 |
|---|---|---|
| **확정** | 유도했거나 문헌으로 확인 | 두께↔각도, 오버스핀 상한 1.25, 미스큐 한계 |
| **문헌** | 실측값을 가져다 씀 (**풀 기준이라 캐롬 재측정 필요**) | 피벗 길이 9.5"/13"/19", 쿠션 반발 0.818 |
| **미확정** | 당구대에서 재야 함 | 커브 계수 C, 회전 감쇠율, 팁→mm 환산, 시스템 숫자표 |

**미확정 상수를 확정인 척 쓰지 않는다.** 이 원칙을 UI에도 그대로 노출한다.

## 기술 스택

| 층 | 선택 | 이유 |
|---|---|---|
| 엔진 | **Unity** | 렌더링·입력·씬만 담당 |
| 물리 | **자체 이벤트 기반 해석적 솔버** | ❌ **PhysX를 쓰지 않는다** — 아래 |
| 플랫폼 | **PC 우선**, 모바일 병행 | 1인칭 정밀 조준은 마우스가 맞다. 모바일은 조준 보조 모드 |
| 데이터 | 물리 상수·시스템 숫자표를 **외부 파일로 분리** | 코드 배포 없이 수정·검증 가능해야 한다 |

### 왜 PhysX를 안 쓰나

| 문제 | 내용 |
|---|---|
| 미끄럼/구름 전이 | 강체 엔진은 마찰을 근사한다. 당구는 **전이 지점**이 결과를 좌우한다 |
| 사이드스핀과 쿠션 | 수직축 회전이 반발각에 주는 영향을 PhysX는 모른다 |
| 적분 오차 | 8쿠션까지 가면 스텝 오차가 **포인트 단위 오차**로 커진다 |
| 결정론 | 리플레이·온라인 동기화·리플레이 분석에 **비트 단위 재현성**이 필요하다 |

**대신 이벤트 기반 해석적 솔버:** 다음 이벤트(전이·정지·공충돌·쿠션충돌)까지의 시간을
닫힌 해로 계산해 그 시점으로 점프한다. 스텝 적분이 없다 → 정확하고, 결정론적이고, 빠르다.

## 아키텍처

```
Unity (렌더 · 입력 · 씬)
  │
  ├─ 조준 시퀀스        6단계 상태 기계 → (속도, 세로타점, 가로타점, 큐각도)
  │
  ├─ 물리 코어          이벤트 기반 솔버 · 결정론 · Unity 비의존
  │    └─ 파라미터       장비(피벗·팁) + 테이블(μs·μr·반발) + 샷(위 4개)
  │
  ├─ 분석 계층          시스템 계산 ↔ 물리 결과의 괴리 분해
  │    └─ 리플레이       "2팁에서 41mm 밀렸다" — 왜 빗나갔는지
  │
  └─ 코치 (AI)          숫자를 말로 옮기는 계층 ⚠️ 계산에는 관여하지 않는다
```

### AI 원칙 — **AI는 숫자를 만들지 않는다. 숫자를 읽는다.**

```
❌ "이 배치는 1쿠션 32를 치세요"        ← AI가 생성한 숫자
✅ 결정론 엔진이 32를 계산 → AI가 "왜 32인지" 설명
```

| 영역 | 담당 |
|---|---|
| 궤적 · 시스템 계산 · 물리 | **결정론 코드** (AI 금지) |
| 설명 · 코칭 · 개인 습관 추출 · 자연어 입력 | **AI** |

핵심 기능은 **오프라인에서 동작해야 한다.** 당구장 네트워크를 신뢰할 수 없다.

> **P1·P2는 각각 한 달이면 답이 나오고, 하나라도 아니면 1~2년을 아낀다.**

## 검증되지 않은 것

**이 레포에서 가장 중요한 섹션.**

| # | 미검증 | 왜 중요한가 | 어떻게 검증하나 |
|:-:|---|---|---|
| 1 | **"이 정확도에 사람이 반응하는가"** | 장르가 세 번 실패했다 | [감도 계산기](https://claude.ai/code/artifact/9fe04f42-d21d-46ed-be87-0e534cffedf9)를 3쿠션 커뮤니티에 보여주고 묻기 |
| 2 | **1인칭 조준이 재미있는가** | 현실에서 몰입인 것이 화면에서는 지루할 수 있다 | P2 프로토타입 |
| 3 | **캐롬 물리 상수** | 문헌 값이 대부분 **풀(포켓볼) 기준**이다 | 당구대 실측 |
| 4 | **커브 계수 C** | 임의값 6.0을 쓰고 있다 | 당구대 실측 |
| 5 | **시스템 숫자표** | 웹 출처 2건뿐, 교재 대조·실측 안 됨 | 교재 + 당구대 |

> **미검증을 미검증이라고 쓰는 것이 이 프로젝트의 설계 원칙이다.**
> 틀린 숫자를 예쁘게 보여주는 것보다 나쁜 것은 없다.
