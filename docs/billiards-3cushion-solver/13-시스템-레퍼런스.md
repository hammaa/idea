# 13. 시스템 레퍼런스 — 다이아몬드는 어디서 쓰나

> **사용자 질문 (2026-08-31):** *"그럼 다이아몬드는 어디서 쓰는 거야? 시스템 종류에 따라 포인트 명칭 계산이 다 다른 거면,
> 많이 쓰는 시스템들의 기본 값들을 탭으로 보여줘."*
>
> 산출물: **[system-reference.html](mockup/system-reference.html)** · [공개 링크](https://claude.ai/code/artifact/f1945414-cdaf-4273-98e5-94427de6db82)

---

## 1. 답 — 다이아몬드와 포인트는 같은 것이다

| | |
|---|---|
| **다이아몬드 (diamond)** | 레일에 박힌 자개 마름모. **물리적 표식** |
| **포인트** | 한국 당구장에서 같은 것을 부르는 말 |
| **다이아몬드 시스템** | 그 표식을 써서 각을 계산하는 방법들의 **계열 이름** |

> **다이아몬드는 "어디서 쓰는 것"이 아니라 전부 다 그것을 쓴다.**
> **다만 시스템마다 같은 표식에 다른 숫자를 매긴다.**

### 세 층을 구분해야 한다

| 층 | 무엇 | 예 |
|---|---|---|
| **물리** | 레일 위의 표식 자체 | 장쿠션 8개 · 단쿠션 4개 · 간격 355.5 mm |
| **일반 좌표** | 위치를 읽는 공통 눈금 ([12번](12-포인트-표기법.md)) | 점 1칸 = **10 포인트** · 장 0–80 / 단 0–40 |
| **시스템 숫자** | 계산용으로 다시 매긴 값 | 파이브앤하프 수구수는 코너가 **50**, 칸당 −5 |

> **"3포인트에 놓고"는 시스템을 말하기 전엔 위치만 가리킨다.**
> 같은 자리가 파이브앤하프에서는 수구수 35이고, 3쿠션수로는 30이다.
> **숫자를 말할 때는 어느 시스템의 어느 값인지를 같이 말해야 한다.**

---

## 2. 시스템은 결국 세 계열이다

이름은 수십 개지만 **무엇을 더하고 빼는가**로 묶으면 셋이다. 새 이름을 만나면 어느 계열인지부터 보면 된다.

| 계열 | 공식 | 성격 | 해당 시스템 |
|---|---|---|---|
| **뺄셈** | `수구수 − 3쿠션수 = 1쿠션수` | 도착점을 정해 놓고 **칠 곳을 역산** | 파이브앤하프, 35 계열 |
| **덧셈** | `수구수 + 1쿠션수 = 3쿠션수` | 칠 곳을 정하고 **갈 곳을 예측** | 플러스, 플러스투, 도쿄 |
| **볼값** | `1적구수 + 도착수 + 기울기` | 빈쿠션이 아니라 **공을 맞히고 도는** 배치 | 앞돌리기, 옆돌리기 |

## 3. 조사 결과 — 확인된 것과 안 된 것

⚠️ **웹으로 확인 가능한 범위가 생각보다 좁았다.** 공식과 당점은 대체로 나오는데, **레일별 숫자표는 거의 안 나온다.**
[02-설계](02-설계.md) 2절의 원칙대로 **추정으로 채우지 않고 확인 상태를 그대로 표시**했다.

| 시스템 | 계열 | 확인 상태 | 확인된 것 |
|---|---|:-:|---|
| **파이브앤하프** | 뺄셈 | 🟡 **부분** | 공식 ✓ · 당점 2~3팁 ✓ · 예시 3건 ✓ · **척도(출처 1건)** · 데이텀 차이 ✓ |
| **플러스** | 덧셈 | 🟢 **확인** | 공식 ✓ · **척도 ✓** · 당점 상단 2팁 ✓ · 예시 ✓ · 패턴 **단-장-장** ✓ (출처 1건) |
| **플러스투** | 덧셈 | 🟡 **부분** | 당점 **중단 3팁** ✓ · 패턴은 플러스와 같은 계열로 추정 / **공식 표기가 자료마다 갈림** |
| **리버스 (역회전)** | 뺄셈 | 🟡 **부분** | 장장단 패턴 ✓ · **보정법** ✓ / 척도 ✗ |
| **도쿄** | 덧셈 | 🟡 **부분** | 원리 ✓ · 당점 2팁(9시/3시) ✓ · 두께 1/3 ✓ · 보정 0.5포인트 ✓ / 척도 ✗ |
| **볼값 (앞·옆돌리기)** | 볼값 | 🟢 **확인** | **공식·기울기 환산·보정 규칙 전부** ✓ |
| 하프 · 로드리게스 · 일출일몰 · 더블레일 · 50/30/15 · 35와 2분의 1 · 크로스테이블 · 엔드레일 | — | 🔴 **이름만** | — |

> **가장 완성도가 높은 건 볼값 시스템이다.** 공식(`1적구수 + 도착수 + 기울기`), 기울기 환산(한 칸 = +2, 반 칸 = +1),
> 보정(1적구 ≥ 4면 도착수 −1, 쿠션에 붙으면 −1 추가), 우선순위(**두께 > 팁수**)까지 전부 나왔다.

### ⭐ 리버스에서 나온 교차 확인

리버스 시스템의 실전 보정 설명이 **이 프로젝트의 물리 모델과 정확히 맞아떨어졌다.**

> *"약하게 치면 1쿠션에서 역회전이 다 죽어 뒤쪽 쿠션에서 실패한다.
> 임팩트 후 큐를 10cm 정도 더 밀어내는 **팔로우 스트로크**로 회전을 유지하면 세게 치지 않고도 살릴 수 있다."*

**[11번](11-타법과-감쇠-모델.md) 3절에서 계산한 그대로다** — 밀어치기(오버스핀)는 미끄럼 구간이 짧아
회전을 훨씬 잘 보존한다 (3쿠션 잔존 31.8% vs 딱 끊어치기 20.8%).

> **당구계의 경험칙과 물리 모델이 독립적으로 같은 결론에 도달했다.**
> 이건 모델이 맞다는 약한 증거이고, 동시에 **이 제품이 왜 유용한지에 대한 답**이기도 하다 —
> 경험칙은 "그렇게 하면 된다"까지만 말하고, 모델은 **얼마나·왜**를 말한다.

## 3-1. ⚠️ 수정 — 플러스 시스템 (2026-08-31)

**사용자 지적: "플러스는 3쿠션인데 그림은 2쿠션이 끝이야."** 맞다. 두 가지가 틀려 있었다.

| 잘못 | 원인 | 수정 |
|---|---|---|
| 도식이 2쿠션에서 끝남 | 패턴 좌표 배열에 점을 3개만 넣음 (출발 + 2쿠션) | **세 패턴 모두 기하 반사로 다시 계산** — 출발 + 3쿠션 |
| 패턴을 `단-장-단`으로 표기 | 자료 확인 없이 추정 | **`단 → 장 → 장`이 맞다** (출처 확인) |

### 다시 계산한 대표 경로 (포인트 좌표, 장 0–80 / 단 0–40)

| 패턴 | 경로 | 해당 시스템 |
|---|---|---|
| **장 → 단 → 장** | 하장 5 출발 → 1쿠션 상장 54 → 2쿠션 우단 20 → 3쿠션 하장 55 | 파이브앤하프 · 도쿄 · 볼값(앞돌리기) |
| **단 → 장 → 장** | 하장 19 출발 → 1쿠션 좌단 20 → 2쿠션 상장 20 → 3쿠션 하장 60 | **플러스 · 플러스투** |
| **장 → 장 → 단** | 하장 5 출발 → 1쿠션 상장 31 → 2쿠션 하장 58 → 3쿠션 우단 34 | 리버스 |

### 그리고 플러스의 척도를 확보했다 — 🟡 부분 → 🟢 확인

| 값 | 척도 |
|---|---|
| **수구수** | 장쿠션에서 읽는다. 한 포인트당 **10** |
| **1쿠션수 (단쿠션)** | 코너와 첫 포인트 **사이**가 **20**, 첫 포인트가 **30**, 거기서 **반 포인트** 더가 **40** |
| **3쿠션수** | **수구수와 같은 척도.** 한 포인트당 **10** |
| 공식 | **수구수 + 1쿠션수 = 3쿠션수** |
| 예시 | 수구수 20 → 도착 50 이면 **1쿠션 30** |
| 당점 | **상단 2팁** |
| 적용 | **뱅크샷 · 볼퍼스트 모두** |
| ⚠️ 볼퍼스트 주의 | 수구수는 현재 위치가 아니라 **앞공을 맞춘 뒤 일직선으로 그었을 때의 장쿠션 포인트** |

> **1쿠션수가 코너 쪽에서 압축된다는 점(20 → 30 → 40이 반 포인트 간격)이 핵심이고, 오독하기 가장 쉬운 곳이다.**
> 이건 아래 「원리」 2번의 실례다 — **눈금을 일부러 왜곡해서 덧셈이 성립하게 만든 것**이다.

## 3-2. 원리 — 시스템은 대체 무엇을 하는가

사용자 요청으로 페이지에 6단계 원리 설명을 추가했다. 요지:

| # | 원리 |
|:-:|---|
| **1** | **시스템은 궤적 관계를 직선으로 편다.** 1쿠션을 옮기면 3쿠션 도착점이 단조롭게 따라 움직인다 — 그 곡선 관계를 **기울기 ±1의 직선으로 만드는 좌표 변환**이 시스템의 숫자다. 곱셈도 삼각함수도 없는 이유 |
| **2** | **그래서 눈금이 레일마다 다르다.** 기하가 균등하지 않으니 눈금을 왜곡해야 직선이 된다. **눈금의 일그러진 모양이 곧 그 시스템이 담은 물리 지식**이고, 시스템을 배운다는 건 공식이 아니라 눈금을 외우는 일이다 |
| **3** | **당점이 규격인 이유.** 직선 관계는 특정 회전량에서만 성립한다. 팁을 바꾸면 지도 전체가 이동한다 — **당점은 권장이 아니라 전제조건** |
| **4** | **보정은 결함이 아니라 근사가 깨지는 지점의 지도.** 직선화는 근사이고 유효 범위가 있다. 대마다·날마다 보정이 다른 것도 당연하다 |
| **5** | **뺄셈과 덧셈은 같은 직선의 다른 표현.** 이항하면 같은 식이다. 갈리는 건 **무엇을 미지수로 두느냐** — 뺄셈은 역산, 덧셈은 예측 |
| **6** | **그래서 시스템이 여러 개다.** 하나의 직선화는 하나의 배치 계열에서만 유효하다. **시스템 개수 = 자주 나오는 쿠션 순서의 개수** |

> ### 이 원리가 이 프로젝트의 출발점이기도 하다
> **시스템은 표준 테이블·표준 당점에서 맞춰진 눈금이고, 당신의 큐와 당신의 대는 그것과 다르다.**
> 그 차이가 몇 포인트인지 계산해 주는 것이 [감도 계산기](mockup/)가 하는 일이다.
> 원리 3번(당점이 전제조건)이 곧 **팁 감도표**의 존재 이유이고, 4번(보정)이 곧 **테이블 캘리브레이션**이다.

## 5. 다음 — 표를 확정하는 4단계

| 순서 | 할 일 |
|:-:|---|
| 1 | **교재 2~3종 대조** — 🟡·🔴 항목의 전체 숫자표를 옮겨 적고 서로 일치하는지 확인 |
| 2 | **데이텀 확정** — 값마다 기준이 다르다. 파이브앤하프는 수구수·1쿠션수 = **당점 기준**, 3쿠션수 = **접촉점 기준**. 섞으면 상시 0.5~1포인트 오차 |
| 3 | **당구대 검증** — 기준선을 실제로 친다. 예: **수구수 50 → 1쿠션 30 → 3쿠션 20**. 안 맞으면 표가 틀렸거나 그 대의 보정이 필요한 것이고, **몇 번 쳐 보면 어느 쪽인지 갈린다** |
| 4 | **그다음에 계산기에 넣는다** — 검증 전 숫자를 도구에 넣으면 틀린 답을 자신 있게 주는 도구가 된다 |

> **3번이 이 아이디어의 유일한 우위가 발휘되는 지점이다** ([01-기획](01-기획.md) 5절).
> 웹에서 몇 시간 뒤져 못 찾은 것을 **당구장에서 한 시간이면 확정할 수 있다.**
