# 01. 가상의 벽 — 실생활 벽을 어떻게 설정하나

> **사용자 질문:** *"공 던져서 벽에 튕겨서 받기. 벽은 그냥 가상의 벽.
> 가상의 벽을 어떻게 실생활 벽으로 설정할까. 그냥 단순히 거리 정도, 높낮이?
> 암벽타기처럼 장애물, 기울기 변화…"*

---

## 1. 벽을 규정하는 최소 파라미터

거리와 높이만으로는 부족하다. **공이 벽에서 어떻게 나오는지**를 정하는 값이 따로 있다.

| # | 파라미터 | 무엇을 정하나 | 없으면 |
|:-:|---|---|---|
| 1 | **거리** | 왕복 시간, 낙하량 | 애초에 못 던짐 |
| 2 | **높이 · 폭** | 조준 가능 영역 | 조준할 곳이 없음 |
| 3 | **기울기** (수직에서 벗어난 각) | 튕겨 나오는 **상하 방향** | 벽이 앞으로 기울면 공이 위로, 뒤로 기울면 아래로 |
| 4 | **반발계수 e** | 되돌아오는 **속도** | 콘크리트인지 석고보드인지가 안 갈림 |
| 5 | **표면 마찰** | 스핀이 **얼마나 먹히고 바뀌는지** | 회전을 준 의미가 사라짐 |
| 6 | **표면 요철 / 장애물** | 예측 불가성 | 난이도 축이 없음 |

> **1·2는 눈으로 잰다. 3·4·5는 눈으로 못 잰다.** 이게 이 문제의 핵심이다.

---

## 2. 설정 방법 세 가지

### ① 수동 입력

거리·높이를 숫자로 넣고, 재질을 목록에서 고른다 (콘크리트 / 벽돌 / 석고 / 나무 / 철판).

| 장점 | 단점 |
|---|---|
| 구현이 가장 쉽다 | **재질 목록은 추정이다.** 같은 콘크리트도 마감에 따라 다르다 |
| 오프라인 동작 | 사용자가 귀찮아서 안 한다 |

### ② 카메라로 측정 (AR)

폰 카메라·LiDAR로 벽 평면을 인식해 거리·기울기·크기를 자동으로 잡는다.

| 장점 | 단점 |
|---|---|
| 1·2·3을 자동으로 얻는다 | **4·5(반발·마찰)는 여전히 못 얻는다** — 카메라는 재질의 탄성을 못 본다 |
| 진입 마찰이 낮다 | 기기 의존, 조명·공간 조건 |

### ③ ⭐ 던져 보고 역산한다

**벽을 재지 말고, 공을 몇 번 던져서 벽의 성질을 역산한다.**

```
온보딩: "저 벽에 세 번만 던져 보세요"
   ① 정면으로 약하게      → 거리 · 반발계수 e
   ② 정면으로 세게         → e 의 속도 의존성
   ③ 회전 주고            → 표면 마찰 · 스핀 전이
        ↓
   되돌아온 궤적에서 4·5를 역산
        ↓
   이후 그 벽은 "내 벽"으로 저장된다
```

> ### **이게 3cushions의 테이블 캘리브레이션과 정확히 같은 구조다.**
> 당구에서도 쿠션 반발과 천 마찰은 눈으로 못 재고, **표준 뱅크샷 몇 개를 쳐서 역산**한다.
> **문제의 형태가 같으므로 해법도 코드도 공유된다.**

| 장점 | 단점 |
|---|---|
| **눈으로 못 재는 4·5를 얻는 유일한 방법** | 사용자가 실제로 던져야 함 |
| 기기 의존 없음 | 초기 3회가 귀찮을 수 있음 |
| **측정 자체가 게임의 일부**가 될 수 있다 | 역산 정확도 검증 필요 |

**권고: ②로 1·2·3을 잡고 ③으로 4·5를 잡는다.** 카메라가 있으면 쓰고, 없으면 ③만으로도 성립한다.

---

## 3. 그리고 여기서 진짜 자산이 나온다

3cushions의 [테이블 보정 DB](../billiards-3cushion-solver/04-수익구조.md)와 같은 논리다.

```
사용자 A가 집 거실 벽을 캘리브레이션
       ↓
같은 장소(체육관·공원 벽·학교 강당)를 다른 사람이 쓰면
       ↓
이미 보정값이 있다
```

| 성질 | 내용 |
|---|---|
| **복제 불가** | 코드로 못 따라온다. 사용자가 있어야만 생긴다 |
| 네트워크 효과 | 커버되는 벽이 늘수록 유용 |
| 구독 정당화 | 장소가 바뀌면 다시 필요 → **끝나지 않는 가치** |

⚠️ **다만 당구장(2만 5천 개, 고정·식별 가능)과 달리 벽은 무한하고 식별이 어렵다.**
"우리 집 거실 벽"은 남과 공유되지 않는다. **공공 장소(체육관·공원)만 공유 가치가 있다.** — 이 차이는 크다.

---

## 4. 장애물과 기울기 — 난이도 축

사용자가 언급한 **"암벽타기처럼 장애물, 기울기 변화"** 는 **벽을 측정 대상에서 설계 대상으로 바꾸는** 발상이다.

| 축 | 쉬움 → 어려움 |
|---|---|
| **기울기** | 수직 → 앞으로 기움(공이 위로 뜸) → 뒤로 기움(발밑으로 떨어짐) |
| **면 분할** | 한 장 평면 → 꺾인 면 → 여러 각도의 패널 |
| **장애물** | 없음 → 고정 돌출 → 움직이는 것 |
| **표적** | 아무 데나 → 지정 구역 → 순서대로 |
| **반발 편차** | 균일 → 구역마다 다른 재질 |

> **여기서 갈림길이 하나 있다.**
> **(A) 실제 벽을 재서 그대로 쓴다** — 현실 밀착, 캘리브레이션이 자산, 그러나 벽이 없으면 못 논다
> **(B) 벽을 게임 안에서 설계한다** — 난이도 조절 자유, 그러나 "실생활 벽"이라는 원안의 매력이 사라진다
>
> **원안은 (A)에서 출발했지만 "장애물·기울기 변화"를 넣는 순간 (B)로 넘어간다.**
> 둘을 섞으려면 **"내 벽을 재서 등록하고, 그 위에 가상 장애물을 얹는다"** 는 형태가 된다 — 그게 AR이다.

## 5. 미해결

| # | 질문 |
|:-:|---|
| 1 | **AR로 갈 것인가.** "실생활 벽"을 진지하게 하면 AR이 자연스러운 귀결인데, 그 순간 개발 규모와 기기 요구가 달라진다 |
| 2 | **받는 것도 조작인가.** 던지기만 조작하고 받기는 자동인가, 받기 타이밍도 입력인가 |
| 3 | 벽이 없는 사용자는? 실내 기본 벽 프리셋이 필요한가 |
| 4 | **역산 정확도** — 3번 던져서 e와 마찰을 얼마나 정확히 얻을 수 있나 (실측 필요) |

> **4번은 실험으로 답이 나온다.** 벽 하나, 공 하나, 슬로우 촬영이면 반나절.
> 3cushions P1과 같은 종류의 작업이라 **같이 하면 한 번에 끝난다.**
