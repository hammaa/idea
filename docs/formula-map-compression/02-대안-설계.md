# 02. 대안 설계 — 아이디어를 살리는 방향

> [01번](01-타당성-검토.md)에서 막힌 것은 **"무손실 + 범용"** 조합뿐이다.
> 둘 중 하나만 풀면 원안의 직관은 그대로 살아난다. 그리고 실제로 그렇게 만든 것들이 이미 있다.

---

## 1. 재해석 — "수식 맵"의 정체는 모델이다

원안의 구조를 다시 보자.

```
[송신측]  데이터  →  맵에서 번호 찾기  →  번호 전송
[수신측]  번호   →  같은 맵에서 수식 실행  →  데이터 복원
```

여기서 결정적인 부분은 **맵이 양쪽에 미리 공유되어 있다**는 점이다. 맵은 전송량에 포함되지 않는다.

이 구조에는 이미 이름이 있다.

| 원안의 표현 | 정식 명칭 |
|---|---|
| 수식 맵 | **모델 / 코드북 / 사전(dictionary)** |
| 맵 번호 | **인덱스 / 잠재 코드(latent) / 부호어** |
| 수식이 바이트를 생성 | **디코더 / 생성 함수** |
| 미리 공유 | **out-of-band 사전 공유** |

**즉 원안은 "압축을 모델링 문제로 본다"는 관점이며, 이건 옳다.**
[01번](01-타당성-검토.md) 6절의 결론과 정확히 맞물린다 — 부호화는 이미 최적이고, 남은 개선은 전부 모델에 있다.

문제는 방향이 아니라 **범용성 요구**였다. 맵이 모든 데이터를 커버해야 한다고 가정한 순간 개수 세기에 걸린다. **특정 부류의 데이터만 커버하겠다고 하면 즉시 성립한다.**

---

## 2. 실제로 작동하는 4가지 형태

### A. 코드북 / 벡터 양자화 (VQ) — 원안과 가장 가까운 기존 기술

원안의 "맵 번호 하나로 여러 바이트 커버"를 **문자 그대로** 구현한 기술이 이미 있다.

- 자주 나오는 바이트 패턴들을 코드북에 넣고, 인덱스만 전송
- LZ77/LZ78 계열(zip, gzip)이 하는 일이 정확히 이것 — 다만 코드북을 **데이터에서 실시간으로 만든다**
- VQ-VAE 등 신경망 코덱은 학습된 코드북을 쓴다

| 원안 대비 | |
|---|---|
| 같은 점 | 인덱스 하나가 여러 바이트를 대체 |
| 다른 점 | 코드북을 **고정 수식이 아니라 데이터로부터 학습** |

→ 고정 수식 집합이 실패하는 이유는 [01번](01-타당성-검토.md) 1-3절(커버율 10^-607). 학습된 코드북은 **실제 등장하는 패턴에만 예산을 쓰기 때문에** 성립한다.

### B. 절차적 생성 — "작은 시드 → 많은 바이트"의 순수형

원안의 직관이 가장 극적으로 실현된 분야는 **데모신(demoscene)** 이다.

| 사례 | 크기 | 내용 |
|---|---|---|
| `.kkrieger` | **96 KB** | 완전한 3D FPS 게임 (텍스처·모델·음악 전부 포함) |
| 4K 인트로 | **4 KB** | 수 분짜리 3D 애니메이션 + 음악 |

원리: 텍스처를 저장하지 않고 **텍스처를 만드는 함수**를 저장한다. 나무 무늬, 대리석, 노이즈는 전부 수식으로 생성된다. 벡터 폰트나 SVG가 비트맵보다 작은 것도 같은 이유다.

> ⚠️ **결정적 차이:** 이건 *주어진 데이터를 압축*하는 게 아니라, *처음부터 수식으로 만든 것*이다.
> 임의의 사진을 넣고 짧은 수식을 찾아내는 건 [01번](01-타당성-검토.md) 5절(계산 불가능성)에 걸린다.
> **"생성은 되지만 역산은 안 된다."** 이 비대칭이 핵심이다.

### C. 신경망 예측기 + 산술 부호화 — 원안에 가장 충실한 현대적 구현

무손실을 유지하면서 모델을 극한까지 밀어붙이는 방향.

```
1. 모델이 "다음 바이트는 무엇일까"를 확률로 예측
2. 예측이 맞으면  → 거의 0비트 소모
   예측이 틀리면  → 그만큼 비트 소모
3. 산술 부호화로 이 확률을 최적 부호로 변환
```

**모델 가중치가 곧 원안의 "수식 맵"이다.** 송수신 양쪽이 같은 모델을 갖고 있으면, 전송하는 건 "모델의 예측을 어떻게 고칠지"뿐이다.

| 구현 | 특징 |
|---|---|
| cmix / NNCP | 무손실 압축 벤치마크 상위권. 느리지만 압축률 최상 |
| LLM 기반 압축 | 대형 언어모델을 예측기로 사용. 텍스트에서 기존 압축기를 크게 앞섬 |

> ⚠️ 구체적 수치는 미검증. LLM 압축 연구(예: "Language Modeling Is Compression", DeepMind 2023 계열)에서
> 이미지·오디오에서도 PNG/FLAC를 앞섰다는 보고가 있으나, **모델 크기를 전송량에 넣지 않는다는 전제**가 붙는다.

**여기서 [01번](01-타당성-검토.md)의 정리는 여전히 지켜진다.** 모델이 예측하지 못하는 데이터(난수)는 오히려 커진다. 모델은 치우침을 더 잘 잡아낼 뿐, 없는 치우침을 만들어내지는 못한다.

### D. 손실 생성 코덱 — 스트리밍 영상에 대한 진짜 답

원안의 *"스트리밍 동영상도 수식 몇 개로"* 는 **무손실을 포기하면 실제로 가능하다.**

```
[송신]  영상 → 인코더 → 아주 작은 잠재 코드
[수신]  잠재 코드 → 생성 모델 → 지각적으로 유사한 영상 복원
```

- 비트 단위로 같지 않다. **사람 눈에 같아 보이면 된다**
- 화상통화에서 얼굴을 매 프레임 보내는 대신, **얼굴 모델 + 표정 파라미터만** 보내는 방식은 이미 상용 제품에 들어가 있다
- 이 경우 실제로 수 kbps 수준까지 내려간다

**원안이 상상한 그림에 가장 가까운 것이 이것이다.** 다만 "압축"이 아니라 "재생성"이라는 점만 다르다.

## 3. 공통 원리 — 왜 이것들은 되고 원안은 안 되나

| | 원안 | 위 A~D |
|---|---|---|
| 대상 | **모든** 데이터 | **특정 부류**의 데이터 |
| 맵 | 미리 정한 고정 수식 | 데이터에서 **학습**하거나 도메인에 특화 |
| 커버 못 하는 입력 | 고려 안 함 | **커지는 것을 인정하고 감수** |
| 복원 | 비트 단위 동일 | 동일(A·C) 또는 지각적 유사(B·D) |

> **한 줄 요약: 압축은 "모든 것을 줄이는 기술"이 아니라 "무엇을 포기할지 고르는 기술"이다.**
> 무손실 압축기는 *드문 데이터*를 포기하고, 손실 압축기는 *지각되지 않는 정보*를 포기한다.
> 원안은 아무것도 포기하지 않으려 했고, 그래서 막혔다.

## 4. 실현 가능한 프로젝트 3안

원안의 문제의식을 유지하면서 실제로 만들 수 있는 것들.

### 안 1. 도메인 특화 무손실 압축기 (난이도 중, 추천)

특정 형식 하나를 골라, 그 형식의 구조를 아는 전용 압축기를 만든다.

| 후보 | 활용할 구조 |
|---|---|
| 서버 로그 | 타임스탬프 증가 패턴, 반복되는 IP·경로, 고정 포맷 |
| 시계열 센서 데이터 | 값이 천천히 변함 → 델타 + 예측 |
| 게임 세이브 파일 | 스키마가 고정, 대부분 필드가 기본값 |
| 특정 회사 JSON API 응답 | 키 이름이 매번 동일 → 스키마 분리 |

**범용 압축기는 이 구조를 모르기 때문에, 도메인 지식만으로 gzip을 이길 수 있다.** 실제로 성과가 나오는 유일한 현실적 경로이며, 원안의 "수식 맵"을 도메인 한정으로 좁힌 형태다.

### 안 2. 절차적 생성 실험 (난이도 하, 학습용)

수식으로 텍스처·음악·지형을 생성하는 4KB 프로그램을 만들어본다.

- "작은 시드 → 많은 출력"의 직관을 손으로 확인할 수 있다
- 동시에 "역산은 안 된다"는 비대칭도 몸으로 알게 된다
- 결과물이 시각적이라 만족감이 크다

### 안 3. LLM 기반 압축기 구현 (난이도 상, 흥미로움)

작은 언어모델 + 산술 부호화로 텍스트 압축기를 만든다.

- 원안의 "수식 맵 = 모델" 구조를 **문자 그대로** 구현하는 것
- 한국어 텍스트에서 xz를 이기는지 직접 측정
- 실용성은 낮다(느리고 모델이 크다). **원리 검증용**

## 5. 참고 — Hutter Prize

이 방향에 진지하게 관심이 있다면 볼 만한 것.

| 항목 | 내용 |
|---|---|
| 내용 | 위키백과 1GB를 최소 크기로 무손실 압축 |
| 상금 | 기존 기록 대비 개선율에 비례해 지급 |
| 취지 | **압축률 = 지능**이라는 전제. 더 잘 압축하려면 더 잘 이해해야 한다 |

원안이 가진 문제의식("더 근본적인 압축이 가능하지 않을까")이 학술적으로 다뤄지는 공인된 무대다. 동시에, **수십 년간 최고 수준 연구자들이 달라붙어 개선폭이 몇 % 단위**라는 사실이 [01번](01-타당성-검토.md)의 결론을 실증한다.
