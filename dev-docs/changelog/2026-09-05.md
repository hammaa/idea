## 3. 앱에 세션 이름이 호스트명으로 뜨던 문제 (10:19~10:20)

사용자 지적: *"이름을 idea-aws 로 하라고 했잖아"* — 모바일 앱 목록에 `ip-172-31-14-156.ap-northeast-2.compute.internal`이 떠 있었다.

### 확인 순서

| 확인 | 결과 |
|---|---|
| `rc_session.sh`의 `NAME` | `idea-aws` — 맞음 |
| screen 래퍼의 cmdline | `claude --remote-control 'idea-aws'` — 맞음 |
| **`comm=claude` 인 실제 프로세스** | **`claude --permission-mode auto` — 인자가 없다** |

### 원인 — claude 는 자동 업데이트 후 기동 인자를 잃는다

```
656644 screen  SCREEN ... bash -lc "... claude --remote-control 'idea-aws' ..."
656646 bash    (래퍼 — 여기엔 원래 인자가 그대로 남아 보인다)
656671 claude  /home/ec2-user/.local/bin/claude --permission-mode auto   ← 인자 소실
```

업데이트가 걸리면 **클로드가 스스로 재실행(exec)하면서 기동 인자를 버린다.**
이름 인자가 사라진 뒤 `/rc`로 재연결되니, 기본값인 **호스트명**이 앱에 표시됐다.

> **래퍼(bash)의 cmdline만 보면 인자가 멀쩡해 보인다.** 그래서 놓치기 쉽다.
> `ps -eo pid,ppid,comm,args | grep claude` 로 **comm=claude 인 프로세스**를 봐야 실제 상태가 나온다.

### 같은 원인으로 깨져 있던 것 하나 더

`rc_restart.sh`의 `rc_pid()`가 **`--remote-control` 문자열로 프로세스를 찾고 있었다.**
그 인자가 사라지니 못 찾는다 — 05:09 재시작 로그에 그대로 남아 있다:

```
[2026-09-05 05:09:50] ✅ 기동 성공
[2026-09-05 05:09:50] 이후: PID=  버전=알수없음      ← 못 찾았다
```

### 조치

| 대상 | 내용 |
|---|---|
| **호스트명** | `hostnamectl set-hostname idea-aws` + `/etc/cloud/cloud.cfg` 의 `preserve_hostname: true` |
| `rc_session.sh` | `--remote-control-session-name-prefix "$NAME"` 추가 |
| `rc_restart.sh` | `rc_pid()` 를 인자 매칭 → **screen 자손 추적**(screen PID → bash → claude)으로 교체 |
| `/etc/hosts` | `127.0.0.1 idea-aws` 추가 |

**호스트명까지 바꾼 이유:** 인자가 날아가는 경로가 있는 이상, 플래그만으로는 다시 깨진다.
**기본값 자체를 `idea-aws`로 만들어야 어느 경로로 떠도 이름이 유지된다.**

> EC2는 재부팅 시 cloud-init이 호스트명을 되돌리므로 `preserve_hostname: true`가 없으면 원복된다.

새 `rc_pid()` 는 현재 프로세스로 검증했다 — PID 656671, 버전 2.1.247 정상 조회.
