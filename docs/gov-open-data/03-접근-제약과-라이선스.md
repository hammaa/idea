# 03. 접근 제약과 라이선스 — 써도 되는가

> 데이터를 **찾는 것**과 **쓰는 것**은 다른 문제다. 개방 ≠ 자유이용.
> 조사일 2026-08-30

---

## 1. 공공누리 — 공공저작물 이용허락 4유형

**[공공누리(KOGL)](https://www.kogl.or.kr/)** 는 공공저작물에 붙는 한국판 CC 라이선스다.
국가·지자체·공공기관이 창작했거나 저작재산권을 가진 저작물이 대상이다.

| 유형 | 조건 | 상업적 이용 | 변경 |
|:-:|---|:-:|:-:|
| **제1유형** | 출처표시 | ✅ | ✅ |
| **제2유형** | 출처표시 + **상업적 이용금지** | ❌ | ✅ |
| **제3유형** | 출처표시 + **변경금지** | ✅ | ❌ |
| **제4유형** | 출처표시 + 상업적 이용금지 + 변경금지 | ❌ | ❌ |

- **출처표시는 4유형 모두 필수**다.
- **사업을 염두에 둔다면 제2·4유형은 쓸 수 없다.** 데이터셋마다 유형이 다르므로 **건별 확인이 필수**다.

> **가장 위험한 오해:** "공공데이터포털에 있으니 다 써도 된다."
> 포털 등재와 라이선스 유형은 별개이며, 일부는 별도 이용약관·제공기관 승인 조건이 붙는다.

## 2. 개방돼 있어도 걸리는 것들

| 제약 | 내용 | 대응 |
|---|---|---|
| **제3자 권리** | 데이터 안에 개인정보·타인 저작물이 섞여 있으면 공공누리와 무관하게 그 부분은 못 쓴다 | 항목 단위로 확인 |
| **API 호출 제한** | 일일/월간 쿼터. 예: KIPRISPlus **월 1,000건 무료** 후 유료 | 캐싱 설계 전제 |
| **활용 목적 신고** | 일부 API는 신청 시 활용 목적을 심사하고, 목적 외 사용을 금지 | 사업 확장 시 재신청 필요 |
| **재배포 제한** | 원본을 그대로 재배포하는 것을 막는 약관이 있는 경우 | 가공·부가가치 형태로 제공 |
| **갱신 중단·스펙 변경** | 예고 없이 필드가 바뀌거나 서비스가 종료됨 | 스키마 검증 + 실패 대비 |
| **기관 개편** | 2025-10-01 통계청→**국가데이터처**, 특허청→**지식재산처**. 도메인·기관코드 변경 | 기관명·URL 하드코딩 금지 |
| **인프라 장애** | 2025-09-26 국가정보자원관리원 화재 → 정보공개포털 등 다수 서비스 중단, **10-31 재개** | 단일 정부 API 의존은 실재하는 리스크 |

## 3. 민감 데이터에 접근하는 3가지 합법 경로

개인정보가 포함된 데이터는 **다운로드가 목표가 될 수 없다.** 대신 세 가지 경로가 있다.

### ① 데이터안심구역

- 미개방 데이터를 **반출 없이** 지정된 안전 공간(또는 원격 접속)에서 분석
- 한국데이터산업진흥원 등이 운영 → [데이터안심구역 안내](https://www.kdata.or.kr/kr/contents/datasafe_02/view.do)
- **분석 결과만 심사 후 반출**

### ② 가명정보 결합

- 서로 다른 기관의 데이터를 **가명처리 후 결합전문기관을 통해** 결합
- 개인정보보호법 근거. 법인·단체면 신청 가능
- 요건: **결합 신청 목적과 활용 목적이 명확**해야 하고, **목적 외 사용 금지**
- 결합 결과는 결합전문기관 **보안구역 내 암호화 저장**, 보관기간 경과 시 **자동 폐기**
- 국가데이터처 결합전문기관 → [통계데이터센터](https://data.mods.go.kr/datalink/)

### ③ 기관별 심사형 제공

| 기관 | 형태 |
|---|---|
| 통계청/국가데이터처 MDIS **인가용** | 원격접근 또는 센터 방문 |
| 심평원 HIRA 빅데이터센터 | 방문 또는 원격시스템, 원시자료 이용 신청 |
| 국민건강보험공단 | 표본코호트·맞춤형 DB 심사 제공 |

> **이 경로들의 공통 성질: 데이터가 나에게 오지 않고, 내가 데이터에게 간다.**
> 서비스를 설계할 때 "데이터를 우리 서버에 적재한다"는 전제가 성립하지 않는다.
> 대신 **분석 코드와 결과만 오간다** — 이건 제약이면서 동시에 **진입장벽(해자)** 이다.

## 4. 공공 마이데이터 — 본인 정보를 본인이 옮기는 경로

- 국민이 **본인에 관한 행정정보**를 제3자에게 전송하도록 요구할 수 있는 제도 (행정안전부)
- 개인정보보호법·전자정부법 기반. 각종 증빙서류 제출을 API 연계로 대체
- **정보공개청구와 성격이 다르다** — 남의 정보가 아니라 **내 정보를 내가 옮기는 것**이라 동의 기반으로 훨씬 넓게 열린다
- 관련 안내: [공공 마이데이터 서비스 안내서 (행정안전부)](https://www.mois.go.kr/frt/bbs/type001/commonSelectBoardArticle.do?bbsId=BBSMSTR_000000000015&nttId=118256)

> 개인 단위 데이터가 필요한 서비스라면, **개방 데이터로 뚫으려 하지 말고 마이데이터 동의 경로가 맞는지** 먼저 봐야 한다.

## 5. 실무 체크리스트

데이터 하나를 서비스에 넣기 전에:

- [ ] **공공누리 유형**을 확인했는가 (제2·4유형이면 상업적 이용 불가)
- [ ] 별도 **이용약관**이나 제공기관 승인 조건이 있는가
- [ ] **개인정보·제3자 저작물**이 섞여 있지 않은가
- [ ] **호출 쿼터**와 유료 구간을 확인했는가
- [ ] **갱신 주기**가 서비스 요구를 만족하는가 (연 1회 갱신 데이터로 실시간 서비스는 못 만든다)
- [ ] **출처표시** 문구를 화면에 넣었는가
- [ ] API가 죽었을 때의 **폴백**이 있는가 (정부 인프라도 5주간 멈춘 적이 있다)
- [ ] 기관 개편으로 **엔드포인트가 바뀔 때** 어디를 고쳐야 하는지 한 곳에 모여 있는가

## 6. 정리 — 세 가지 벽

| 벽 | 정체 | 넘는 법 |
|---|---|---|
| **찾기의 벽** | 어느 기관이 갖고 있는지 모른다 | 원문공개 검색 → 국가중점데이터 → 도메인 전용 포털 순으로 탐색 |
| **형태의 벽** | HWP·PDF·비표준 코드·기관별 상이한 스키마 | 정제·정규화 자체가 부가가치. **개방량 20배 vs 활용량 5,413배**가 이 벽의 크기다 |
| **권리의 벽** | 개인정보·영업비밀 (비공개 사유의 **48%**) | 가공으로 못 넘음. 안심구역·가명정보결합·마이데이터 중 하나를 골라야 함 |

> **첫 번째 벽은 지식으로, 두 번째 벽은 노동으로, 세 번째 벽은 자격으로 넘는다.**
> 그리고 셋 중 경쟁자가 따라오기 가장 어려운 것은 세 번째다.
