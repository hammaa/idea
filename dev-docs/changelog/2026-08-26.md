## 2. `idea-aws` AWS 서버 구성 (신규)

trader 레포의 `trader-aws` 운영 패턴을 그대로 참고해 새 서버를 세팅했다.

| 항목 | 값 |
|---|---|
| 호스트 | `idea-aws` (Windows hosts 파일에 이미 등록: 43.203.241.72) |
| 인스턴스 | t4g.small (ARM, aarch64), 2GB RAM, 20GB |
| OS | Amazon Linux 2023 |

### 2-1. 기본 도구 설치

- `git` — dnf로 설치.
- `claude` CLI — **네이티브 바이너리**로 설치 (`curl -fsSL https://claude.ai/install.sh | bash`). Node.js/npm 불필요 (예전 npm 설치 방식과 다름, 사용자가 직접 정정).

### 2-2. GitHub 저장소 권한

- 서버 전용 ed25519 SSH 키(`~/.ssh/id_ed25519`, 코멘트 `idea-aws-deploy-key`) 생성.
- GitHub `hammaaa/idea` 저장소에 **Deploy key(쓰기 권한)**로 등록(사용자가 GitHub에서 직접 처리) → 서버가 이 레포 하나에만 clone/pull/push 가능.
- `~/idea`에 레포 클론, `~/.ssh/config`에 `github.com` 기본 identity 등록(매번 `GIT_SSH_COMMAND` 안 붙여도 됨), `git config user.name/email` = `hammaaa` / `hammaaa@gmail.com` 설정.

### 2-3. Remote Control 세션 (`rc_session.sh`)

- trader 레포의 `scripts/aws-claude/rc_session.sh`를 이 레포용으로 이식(`RC_NAME=idea-aws`, `RC_WORKDIR=~/idea`) → `scripts/aws-claude/rc_session.sh`.
- full-scope 로그인 필요 (`CLAUDE_CODE_OAUTH_TOKEN`은 추론 전용이라 Remote Control 목록에 안 뜬다 — trader 서버 구축 때 이미 겪은 문제). `rc_session.sh login`으로 헤드리스 OAuth 진행 → 사용자가 URL 승인 후 받은 코드를 전달 → 서버에 주입해 완료.
- 최초 `start` 후 목록에 안 떴던 이유: `claude --remote-control` 최초 실행 시 뜨는 **"이 폴더를 신뢰합니까?" 확인 프롬프트**에서 그냥 멈춰 있었음. `screen`에 Enter를 보내 확인 → 정상 등록.
- 검증: `ListAgents`에 `idea-aws · Remote Control · idle` 로 등재 확인.

### 2-4. 문서화

- `docs/aws/SERVER.md` 신설 — 접속 정보, 스펙, 설치 현황 체크리스트, Remote Control/git 권한 절차 정리.

## 3. 작업 흐름 가이드 이식

- trader 레포 `dev-docs/guides/workflow-guide.md`를 참고해 `dev-docs/guides/workflow-guide.md` 신설.
- 한 가지 의도적으로 다르게: trader는 "오늘 정리" 때만 자동 push였지만, 이 레포는 **문서를 고치는 모든 순간 commit+push를 항상 즉시** 하는 것으로 강화.
- `CLAUDE.md` Standing rules에 이 가이드를 참조하도록 갱신 + "오늘일 정리해" 절차(변경 요약 → changelog 작성 → 아이디어 목록 갱신 → commit/push) 추가.
